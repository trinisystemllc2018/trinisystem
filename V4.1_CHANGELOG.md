# v4.1 — Template Color Match + Cursor Fix

## Two issues fixed

### 1. Color was wrong (purple → orange/red)
The reference template had `--primary: 262° purple` defined in its design tokens (a leftover from the shadcn/ui starter), but the actual hero rendering uses an **orange #f97316 → red #ef4444 gradient** hardcoded in the components. I trusted the token, not the rendered output.

**Now matches the template:**
- Hero "Fixed Today." headline: orange→red gradient with shimmer
- All CTAs: orange→red gradient (matches template's "Start Free Trial")
- Hero orbs: orange + red + amber (was purple/blue/emerald)
- Aurora ribbon: orange/red/amber tones
- Custom scrollbar: orange
- Custom cursor: orange dot, red on hover
- Navbar phone button: orange→red gradient
- Footer header strip: warm orange-tinted (was purple)

### 2. Cursor not visible during scroll
The previous cursor used `mouseleave` on `document` which fired aggressively during scroll, hiding the cursor incorrectly. Fixed by:
- Switched to `pointermove` / `pointerleave` events
- Only hides when pointer truly leaves the window (`relatedTarget` null)
- Recomputes hover target every frame via `elementFromPoint(mouseX, mouseY)` — this keeps hover state correct during scroll even without mouse movement
- Z-index bumped from 9999 → 99999 to render above all scrolling content
- Forced GPU layer with `transform-style: preserve-3d`
